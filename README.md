# Каталог товаров

Telegram-бот, через который администратор добавляет товары (фото + название + описание), и веб-страница «Каталог» со списком товаров. Страница открывается в обычном браузере и внутри Telegram как Mini App и **обновляется в реальном времени**: новые товары появляются, удалённые исчезают без перезагрузки.

**Стек:** Next.js (App Router) · FastAPI · aiogram 3 · PostgreSQL · MinIO · nginx · Docker Compose

## Быстрый старт

Если `.env` уже настроен (см. [Первая настройка](#первая-настройка-один-раз)):

```bash
cd ~/Desktop/catalog
make start
```

1. Откройте http://localhost:8080 — страница «Каталог».
2. Напишите боту `/start` в Telegram, нажмите «Открыть каталог».
3. Отправьте боту фото с подписью — товар сразу появится на обеих страницах.

Остановить: `make stop`.

## Все команды

Все команды собраны в `Makefile`. Список выводит просто `make`.

| Команда | Что делает |
|---|---|
| `make start` | Запустить всё: туннель, сервисы, вебхук бота |
| `make stop` | Остановить всё, данные сохраняются |
| `make restart` | Перезапустить всё с новым туннелем |
| `make rebuild` | Пересобрать сервисы после правок кода (туннель не трогает) |
| `make status` | Статус всех сервисов |
| `make logs` | Логи всех сервисов в реальном времени |
| `make logs-bot` / `make logs-backend` | Логи бота / backend |
| `make webhook-info` | Состояние вебхука в Telegram: адрес, очередь, последняя ошибка |
| `make clear-catalog` | Удалить все товары и картинки (открытые страницы очистятся сами) |
| `make reset` | **Опасно:** удалить базу и хранилище целиком, запустить с нуля (спрашивает подтверждение) |
| `make kill-replicas` | Тест отказоустойчивости: убить по одной копии backend, bot, frontend |
| `make heal` | Вернуть убитые копии |

## Первая настройка (один раз)

### 1. Установить программы

- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- cloudflared — даёт HTTPS-адрес, без которого Telegram не работает:
  ```bash
  brew install cloudflared
  ```

### 2. Создать бота

1. Откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите имя бота, затем username, который заканчивается на `bot`.
3. Скопируйте токен вида `1234567890:AAH...`. Никому его не показывайте: с ним можно управлять ботом. Если токен утёк, сбросьте его в BotFather командой `/revoke`.

### 3. Узнать свой Telegram ID

Напишите что угодно боту [@userinfobot](https://t.me/userinfobot), он ответит вашим ID. Этот ID получит права администратора.

### 4. Заполнить `.env`

```bash
cp .env.example .env
```

| Переменная | Что вписать |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `ADMIN_IDS` | ваш Telegram ID; несколько ID через запятую |
| `WEBHOOK_SECRET` | результат `openssl rand -hex 32` |
| `INTERNAL_API_TOKEN` | ещё один результат `openssl rand -hex 32` |
| `POSTGRES_PASSWORD`, `MINIO_ROOT_PASSWORD` | любые пароли |
| `PUBLIC_URL` | не трогать, `make start` впишет сам |
| `BACKEND_REPLICAS`, `BOT_REPLICAS`, `FRONTEND_REPLICAS` | сколько копий каждого сервиса запускать (по умолчанию 2) |

> Пароль PostgreSQL задаётся только при первом запуске. Если поменять его потом, backend не подключится к базе. Чтобы начать с чистой базы: `make reset` (удалит все товары).

## Запуск и остановка

### Запуск

```bash
make start
```

Что происходит (скрипт `start.sh`):
1. Проверяет, что есть `.env`, `cloudflared` и запущен Docker.
2. Запускает туннель `cloudflared` в фоне и получает публичный адрес `https://….trycloudflare.com`.
3. Записывает этот адрес в `PUBLIC_URL` в `.env`.
4. Собирает и запускает все сервисы (`docker compose up -d --build`). При первом запуске это занимает несколько минут.
5. Регистрирует вебхук бота в Telegram на новый адрес.
6. Печатает «Готово» и адреса.

Терминал после этого можно закрыть: туннель и сервисы продолжат работать.

### Остановка

```bash
make stop
```

Останавливает все сервисы и туннель. Товары и картинки сохраняются до следующего запуска.

### Когда запускать заново

Бесплатный туннель живёт, пока работает процесс `cloudflared`, и при каждом запуске выдаёт **новый адрес**. Если вы перезагрузили компьютер, он долго спал или бот перестал отвечать, просто выполните `make start` ещё раз: команда поднимет новый туннель и перенастроит бота.

### После правок кода

```bash
make rebuild
```

Пересобирает изменённые сервисы и применяет новые миграции базы. Туннель и вебхук не трогает.

### Вручную, без скриптов

```bash
# окно 1: туннель, не закрывать
cloudflared tunnel --url http://localhost:8080

# окно 2: подставить адрес из окна 1
sed -i '' 's|^PUBLIC_URL=.*|PUBLIC_URL=https://ВАШ-АДРЕС.trycloudflare.com|' .env
docker compose up -d --build
docker compose run --rm --build bot-webhook
```

## Как тестировать

### 1. Все сервисы запущены

```bash
make status
```

| Сервис | Должен быть |
|---|---|
| `backend` ×2, `bot` ×2 | `Up (healthy)` |
| `frontend` ×2, `nginx`, `postgres`, `minio` | `Up` |
| `migrate`, `minio-init` | `Exited (0)` — одноразовые задачи, так и должно быть |

### 2. Каталог в браузере

Откройте http://localhost:8080. Должна открыться страница «Каталог» с надписью «Товаров пока нет» или со списком товаров.

### 3. Бот

| Действие | Ожидаемый ответ |
|---|---|
| `/start` | «У меня есть товар» + кнопка «Открыть каталог». Админу ещё «Вы администратор…» и кнопка «Создать товар» |
| Любой текст | «У меня есть товар» + кнопка «Открыть каталог» |
| Кнопка «Создать товар» или `/create` (админ) | Подсказка, как отправить товар |
| Фото **без подписи** (админ) | «Не вижу названия…» |
| **Фото с подписью** (админ), см. пример ниже | «Товар «Apple AirPods Max» добавлен в каталог» |
| Фото с подписью от **не админа** | «У меня есть товар», товар **не** создаётся |
| Кнопка «Открыть каталог» | Каталог открывается внутри Telegram |

Пример подписи к фото:

```
Apple AirPods Max
Цвет: Серебристый
Цена: 549 €
```

- **Первая строка — название** (до 255 символов). Приставку «Название:» бот убирает сам.
- **Остальные строки — описание** (необязательно). Показывается в карточке под названием.

Фото можно отправить и файлом (JPEG/PNG/WebP, до 10 МБ).

### 4. Обновление в реальном времени

1. Откройте каталог в браузере (http://localhost:8080) и в Telegram (кнопка «Открыть каталог»). Оставьте обе страницы открытыми.
2. Отправьте боту фото с подписью — товар **сразу появляется на обеих страницах**, без обновления.
3. Выполните `make clear-catalog` — товары **сразу исчезают с обеих страниц**.

Удаление работает так же, если удалить товар напрямую в базе:

```bash
docker compose exec postgres psql -U catalog -d catalog -c "DELETE FROM products WHERE id = 1;"
```

### 5. Отказоустойчивость

```bash
make kill-replicas     # убить backend-1, bot-1, frontend-1
```

Сразу после этого:
- обновите каталог в браузере — должен открываться;
- отправьте боту фото с подписью — товар должен добавиться и сразу появиться на открытых страницах.

Работу подхватили оставшиеся копии. Вернуть убитые:

```bash
make heal
```

Масштабирование до любого числа копий:

```bash
docker compose up -d --scale backend=3 --scale bot=3 --scale frontend=3
```

В логах видно, что сообщения обрабатывают разные копии:

```bash
make logs-bot
# bot-1 | ... Update id=... is handled
# bot-2 | ... Update id=... is handled
```

### 6. API напрямую

```bash
# Список товаров
curl http://localhost:8080/api/products

# Без секретного токена создать товар нельзя: 401
curl -i -X POST http://localhost:8080/api/products -F title=x -F image=@photo.jpg

# С токеном: 201
TOKEN=$(grep ^INTERNAL_API_TOKEN= .env | cut -d= -f2-)
curl -X POST http://localhost:8080/api/products \
  -H "X-Internal-Token: $TOKEN" \
  -H "Idempotency-Key: test-1" \
  -F title="Тест" -F description="Описание" -F "image=@photo.jpg;type=image/jpeg"

# Тот же запрос ещё раз: 200 и тот же товар, дубль не создаётся
```

## Если что-то не работает

Первым делом: `make status` и `make webhook-info`.

| Симптом | Причина и решение |
|---|---|
| Бот не отвечает | Чаще всего закрылся туннель. Выполните `make start` |
| `make webhook-info` показывает `530` | Туннель не работает — `make start` |
| `make webhook-info` показывает `502` | Сервисы бота перезапускались. Если ошибка старая (`last_error_date`) и `pending_update_count: 0` — всё в порядке |
| `make webhook-info` показывает `Unauthorized` | Неверный `BOT_TOKEN` в `.env` |
| Бот отвечает, но не даёт создать товар | Вашего ID нет в `ADMIN_IDS`. Исправьте и выполните `make rebuild` |
| «Название слишком длинное» | Первая строка подписи длиннее 255 символов. Перенесите детали на следующие строки |
| «Не удалось сохранить товар» | `make logs-backend` |
| Каталог в Telegram не открывается | `PUBLIC_URL` устарел — `make start` |
| Картинки не грузятся | `docker compose logs minio-init nginx` |
| Каталог не обновляется сам | Перезагрузите страницу один раз. Проверьте `make logs-backend`: должно быть `Listening for product events` |
| «Docker не запущен» | Откройте Docker Desktop |
| `backend` и `bot` в статусе `Created`, а не `Up` | Упала миграция: `docker compose logs migrate` |

## Как всё устроено

```
                      ┌──────────────────── Docker на вашем компьютере ────────────────────┐
Telegram ──┐          │                                                                    │
           ├─► туннель ─► nginx :8080 ─┬─ /tg/webhook ──► bot ×2 ─────┐                     │
Браузер ───┘  (HTTPS) │                │                              ▼                     │
                      │                ├─ /api/ ─────────────► backend ×2 ─┬─► PostgreSQL   │
                      │                ├─ /api/products/ws ──►  (WebSocket) │   (LISTEN/     │
                      │                │                                    │    NOTIFY)     │
                      │                │                                    └─► MinIO        │
                      │                ├─ /media/ ───────────► MinIO (картинки)             │
                      │                └─ / ─────────────────► frontend ×2                  │
                      └────────────────────────────────────────────────────────────────────┘
```

| Компонент | Роль |
|---|---|
| **cloudflared** | Даёт публичный HTTPS-адрес. Telegram работает только с HTTPS |
| **nginx** | Единственная точка входа. Раздаёт запросы по путям и между копиями сервисов, держит постоянные соединения с ними, сжимает ответы (gzip), кеширует картинки. Если копия не отвечает, отправляет запрос в другую |
| **bot** | aiogram 3. Принимает сообщения от Telegram через вебхук, создаёт товары через backend |
| **backend** | FastAPI. Единственный, кто пишет в PostgreSQL и MinIO. Рассылает живые обновления по WebSocket |
| **frontend** | Next.js. Рендерит страницу «Каталог» на сервере, в браузере подключается к живым обновлениям |
| **PostgreSQL** | Таблица `products`. Триггер на удаление и канал `LISTEN/NOTIFY` для живых обновлений |
| **MinIO** | S3-хранилище, бакет `products` с картинками |
| **migrate** | Одноразово применяет миграции Alembic перед стартом backend |
| **minio-init** | Одноразово создаёт бакет и открывает его на чтение |
| **bot-webhook** | Регистрирует вебхук в Telegram. Не запускается сам при `docker compose up`, его вызывает `make start`, когда адрес туннеля уже известен |

### Таблица `products`

| Поле | Тип | Описание |
|---|---|---|
| `id` | bigint | Номер товара |
| `title` | varchar(255) | Название |
| `description` | text, может быть пустым | Описание |
| `image_key` | varchar(255) | Имя файла картинки в MinIO |
| `external_id` | varchar(128), уникальное | Ключ защиты от дублей: `tg:<chat_id>:<message_id>` |
| `created_at` | timestamptz | Дата добавления |

Миграции (`backend/migrations/versions/`):
- `0001` — таблица `products`;
- `0002` — поле `description`;
- `0003` — триггеры, которые при `DELETE`/`TRUNCATE` рассылают событие об удалении.

## Как работает бот

### Пользователь пишет боту

1. Пользователь отправляет `/start` или любой текст.
2. Telegram присылает POST на `PUBLIC_URL/tg/webhook` с заголовком `X-Telegram-Bot-Api-Secret-Token`.
3. Туннель передаёт запрос в nginx, nginx — в одну из копий бота.
4. Бот сверяет секрет с `WEBHOOK_SECRET`; чужие запросы получают `401`.
5. Бот отвечает «У меня есть товар» и кнопкой Mini App «Открыть каталог». Админу дополнительно показывает кнопку «Создать товар».
6. Бот отвечает Telegram `200 OK` только после обработки. Если копия упала посреди обработки, Telegram пришлёт сообщение снова.

### Администратор добавляет товар

1. Админ отправляет **одно сообщение**: фото + подпись.
2. Бот проверяет, что отправитель есть в `ADMIN_IDS`. Сообщения не-админов уходят в общий обработчик («У меня есть товар»).
3. Бот делит подпись: первая строка — название (без приставки «Название:»), остальные — описание. Название не может быть пустым или длиннее 255 символов.
4. Бот скачивает фото с серверов Telegram.
5. Бот отправляет `POST /api/products` (multipart: `title`, `description`, `image`) с заголовками:
   - `X-Internal-Token` — общий секрет бота и backend;
   - `Idempotency-Key: tg:<chat_id>:<message_id>` — ключ защиты от дублей.
6. Бот отвечает «Товар «…» добавлен в каталог» и кнопкой «Открыть каталог».

Код: `bot/app/handlers/common.py` (ответ всем), `bot/app/handlers/admin.py` (создание товара), `bot/app/main.py` (вебхук-сервер).

## Как работает backend

### Создание товара (`POST /api/products`)

1. Проверяет `X-Internal-Token`; без него — `401`.
2. Если товар с таким `Idempotency-Key` уже есть — сразу возвращает его (`200`).
3. Проверяет тип файла (JPEG/PNG/WebP) и размер (до 10 МБ).
4. Загружает картинку в MinIO под случайным именем `<uuid>.jpg`.
5. В одной транзакции:
   - `INSERT … ON CONFLICT (external_id) DO NOTHING` — если две копии одновременно создают один товар, запишется только один;
   - `pg_notify('products', {"type":"product", ...})` — событие для живых обновлений.
6. Коммит. Только после него PostgreSQL рассылает событие.
7. Если запись не удалась — удаляет загруженную картинку из MinIO, чтобы не оставлять мусор.

### Список товаров (`GET /api/products`)

Читает товары из PostgreSQL (новые первыми) и строит ссылки на картинки: `/media/<image_key>`. Ссылки относительные, поэтому работают на любом адресе: localhost, туннель, свой домен.

### Живые обновления (`/api/products/ws`)

1. При старте каждая копия backend открывает одно подключение к PostgreSQL и выполняет `LISTEN products`.
2. Страница каталога подключается по WebSocket к любой копии backend (её выбирает nginx).
3. Событие в канал `products` приходит из двух мест:
   - **создание** — backend сам вызывает `pg_notify` при создании товара;
   - **удаление** — триггер в PostgreSQL на любой `DELETE` (бот, API, ручной SQL) отправляет `{"type":"deleted","ids":[...]}`; на `TRUNCATE` и на удаление больше 500 товаров — `{"type":"resync"}`.
4. PostgreSQL доставляет событие **всем** копиям backend, каждая пересылает его своим открытым страницам.
5. Раз в 20 секунд backend шлёт `ping`, чтобы прокси не закрывали тихое соединение.
6. Если копия потеряла связь с PostgreSQL, она переподключается и отправляет страницам `resync`, чтобы те перезагрузили список.

Код: `backend/app/api/products.py` (API и WebSocket), `backend/app/events.py` (LISTEN и рассылка), `backend/app/storage.py` (MinIO).

## Как работает frontend

1. Пользователь открывает каталог: кнопка в Telegram или адрес в браузере.
2. nginx передаёт запрос во frontend.
3. Next.js на сервере запрашивает `GET /api/products` и отдаёт готовый HTML с товарами.
4. Браузер загружает картинки по `/media/…`, nginx берёт их из MinIO. Имена картинок уникальны и не меняются, поэтому nginx разрешает браузеру кешировать их навсегда.
5. Страница открывает WebSocket к `/api/products/ws`:
   - `product` — добавляет карточку в начало списка;
   - `deleted` — убирает карточки с этими `id`;
   - `resync` — заново загружает весь список.
6. При каждом (пере)подключении страница заново загружает список, чтобы не пропустить изменения, пока связи не было. Если соединение оборвалось, переподключается через 2 секунды.
7. Внутри Telegram подключается `telegram-web-app.js`: страница разворачивается на весь экран и берёт цвета темы Telegram. Вне Telegram — обычная страница, светлая или тёмная по настройкам системы.

> Используется WebSocket, а не SSE: бесплатный туннель Cloudflare (trycloudflare) буферизует SSE, и события не доходят до Telegram.

Код: `frontend/app/page.tsx` (серверная загрузка), `frontend/app/catalog.tsx` (список и живые обновления), `frontend/app/globals.css` (стили).

## Отказоустойчивость: несколько копий каждого сервиса

По умолчанию запускается по 2 копии `backend`, `bot` и `frontend` (`*_REPLICAS` в `.env`).

| Решение | Зачем |
|---|---|
| **Сервисы ничего не хранят у себя** | Всё состояние лежит в PostgreSQL и MinIO, поэтому любой запрос может обработать любая копия |
| **Вебхук вместо polling** | При polling две копии бота конфликтуют (Telegram отвечает `409 Conflict`). С вебхуком nginx делит сообщения между копиями |
| **Нет состояния диалога (FSM)** | Товар создаётся одним сообщением, поэтому не нужно помнить «шаг диалога» между копиями |
| **Ответ Telegram только после обработки** | Если копия упала посреди обработки, Telegram не получит `200` и пришлёт сообщение снова, уже в живую копию |
| **Idempotency-Key + уникальный индекс** | Повторно присланное сообщение не создаст дубль, даже если две копии обрабатывают его одновременно |
| **Живые обновления через PostgreSQL `LISTEN/NOTIFY`** | Копии backend не знают друг о друге. События рассылает сам PostgreSQL всем копиям, поэтому каждая страница их получит, к какой бы копии она ни была подключена |
| **Удаление через триггер в базе** | Событие об удалении отправляется при любом удалении, кто бы его ни сделал |
| **Переподключение + resync на клиенте** | Если копия backend упала, страница переподключится к другой и догрузит пропущенное |
| **Одноразовые `migrate`, `minio-init`, `bot-webhook`** | Миграции, создание бакета и регистрация вебхука выполняются один раз, копии при старте не мешают друг другу |
| **nginx `resolve` + `proxy_next_upstream`** | nginx замечает новые и перезапущенные копии и повторяет запрос на другой копии при ошибке |
| **Healthcheck** | Docker видит зависшие копии `backend` и `bot` |

## API

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| `GET` | `/api/products?limit=50&offset=0` | публичный | Список товаров, новые первыми. Ответ: `{items: [...], total}` |
| `POST` | `/api/products` | `X-Internal-Token` | Создать товар. `multipart/form-data`: `title` (до 255), `description` (необязательно, до 2000), `image`. Необязательный заголовок `Idempotency-Key`. `201` — создан, `200` — уже был создан с этим ключом |
| `WS` | `/api/products/ws` | публичный | Живые обновления, см. ниже |
| `GET` | `/health` | внутренний | Проверка работоспособности backend и bot |

Товар в ответах:

```json
{
  "id": 1,
  "title": "Apple AirPods Max",
  "description": "Цвет: Серебристый\nЦена: 549 €",
  "image_url": "/media/<uuid>.jpg",
  "created_at": "2026-10-30T18:13:17.979507Z"
}
```

Сообщения WebSocket:

| Сообщение | Когда |
|---|---|
| `{"type":"product","product":{...}}` | Создан товар |
| `{"type":"deleted","ids":[1,2]}` | Удалены товары |
| `{"type":"resync"}` | Нужно перезагрузить список целиком |
| `{"type":"ping"}` | Раз в 20 секунд, поддержание соединения |

Коды ошибок `POST /api/products`: `401` (нет или неверный токен), `413` (файл больше 10 МБ), `415` (не JPEG/PNG/WebP), `422` (пустое название или файл).

│   ├── app/models.py              модель Product
